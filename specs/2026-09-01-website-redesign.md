# Future Focus Solutions — Clay-Inspired Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-skin the entire Future Focus Solutions static site from the current dark "Binance-faithful" theme to a cream, warm, Clay.com-inspired theme (per `DESIGN-New.md` / `client-approved-reference-new.html`), keep the logo colors untouched, narrow the live navigation to the new IA (Home / About Us / Services [Financial Planning, Mutual Funds, Insurance] / Market Insights [Stocks, Commodities] / Contact Us), and freeze the four services that fall outside the new IA (Retirement & Tax Planning, Loans, Real Estate, Debt Collection & Recovery) without deleting them.

**Architecture:** The site is generated by `build.py` from `business.json` + per-page fragments in `pages/*.html`, assembled by one shared `render_shell()` function (Tailwind-CDN config + header/nav/footer/floating-actions markup, identical for every page). Because nearly every fragment references only *named* Tailwind theme tokens (not raw hex), most of the re-skin happens by redefining the token palette inside `render_shell()`'s `tailwind.config`; fragments only need mechanical class renames (old dark-token names → new cream-token names) plus a `text-white` → `text-ink` sweep, with a couple of context-sensitive exceptions called out per task.

**Tech Stack:** Static HTML, Tailwind CSS via CDN (JIT, configured inline per page), vanilla JS, Python 3 build script (`build.py`), no test suite / no bundler — verification is `python3 build.py` (must exit 0, print all "built ..." lines) + visual review by opening the generated HTML in a browser.

**Spec:** `docs/redesign.md` (task brief), `DESIGN-New.md` (Clay.com design-system analysis), `client-approved-reference-new.html` (client-approved look-and-feel reference, generic/healthcare placeholder content — colors/type/structure only, not copy), `docs/prompt.md` (original technical requirements — must not regress), `docs/Notes.md` (new nav/menu structure agreed with client).

## Global Constraints

- Do not change the logo's own colors (`assets/logo/logo-color.png`, `logo-white.png`, `icon-color.png`, `icon-white.png` stay pixel-identical). Sampled logo colors: deep green `#04442C`, gold `#FBBE07`.
- Keep the overall look and feel of `client-approved-reference-new.html` (cream canvas, big rounded cards, Outfit-for-display + Inter-for-body pairing, generous whitespace) but recolor the saturated multi-hue Clay cards to a green/gold/cream palette derived from the logo instead of Clay's pink/teal/lavender/peach/ochre.
- Do not remove any feature/section called out in `docs/prompt.md` (sticky auto-hide header, floating scroll-top/call/WhatsApp buttons, WhatsApp-redirect enquiry form, 5-6 testimonials, scroll-reveal motion, `{{TOKEN}}` fragment placeholders resolved by `build.py`).
- New nav is authoritative for what's **linked**, not for what exists on disk: `Retirement & Tax Planning`, `Loans`, `Real Estate`, `Debt Collection & Recovery` pages must keep building/existing at their current URLs (no 404s for old links) but must not be reachable from any nav, dropdown, footer column, services grid, or home page grid, and must carry `<meta name="robots" content="noindex,nofollow">`.
- Every internal page must still validate as the *build output* of `build.py` — never hand-edit `index.html`, `about/index.html`, etc. directly (except the one-time manual `noindex` edit to the 4 frozen pages' already-built HTML, since they're being removed from the `PAGES` build loop).
- No new copy/content invented beyond what's needed to trim now-orphaned promotional lists (hero eyebrow, trust-strip stat, "What We Help With" grid, Services grid) down to the 3 live services — no new marketing claims added anywhere.

Fonts: `Inter` (400/500/600/700) for body/nav/buttons, `Outfit` (500/600) for display headings — exactly as loaded in `client-approved-reference-new.html`'s `<link>` tag. Headings use `font-display font-medium` (Outfit 500) per Clay's "never bolder than 500" rule; only the nav wordmark/logo lockup and card titles may go to `font-semibold` (600). Replace the current `font-sans font-extrabold` / `font-bold` on all `h1`/`h2`/`h3` in every fragment with `font-display font-medium` (h1/h2) or `font-display font-semibold` (h3/card titles).

Leave list-style sections (Financial Planning/Mutual Funds/Market Insights subsections, testimonials, contact detail cards) as plain `surface-card`/`canvas` alternating bands — Clay's own reference doesn't force every section into a saturated card either.
